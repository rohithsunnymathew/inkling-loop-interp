The attacker began with a phishing email that impersonated the payroll team and carried a macro-enabled spreadsheet. When the finance officer enabled content, the macro launched PowerShell with an encoded command, which downloaded a second-stage loader from a compromised WordPress site. The loader injected shellcode into a legitimate process to evade the endpoint agent, then established persistence through a scheduled task named to resemble a Windows update. Within an hour the implant was beaconing to its command-and-control server over HTTPS every sixty seconds with random jitter.
From that foothold the intruder dumped credentials from LSASS memory using a renamed copy of a common tool. One harvested hash belonged to a service account with local administrator rights on most servers, so lateral movement was trivial: the attacker used pass-the-hash over SMB and remote WMI calls to reach the file servers. Kerberoasting produced tickets for several accounts with weak passwords, and offline cracking recovered two of them within a day. One of those accounts was a member of a group with replication rights, which allowed a DCSync attack against the domain controller and exposed the krbtgt hash.
Detection engineers later reconstructed the timeline from Sentinel logs. Sign-in logs showed impossible travel for a privileged account, Defender raised an alert for suspicious LSASS access, and DNS telemetry revealed regular queries to a newly registered domain. A Sigma rule for encoded PowerShell command lines would have fired on the first stage, and a KQL query joining process creation events with network connections exposed every host that contacted the malicious infrastructure. The analysts mapped each step to MITRE ATT&CK techniques, from initial access through credential access, lateral movement, collection and exfiltration.
Exfiltration happened in compressed, encrypted archives split into small chunks and uploaded to cloud storage, which kept each transfer below the data loss prevention thresholds. Before deploying ransomware, the operators disabled backups, deleted volume shadow copies and stopped database services so that files would not be locked. The ransom note threatened to leak the stolen data on a public extortion site if payment was not made in cryptocurrency within seventy-two hours.
Incident responders isolated affected hosts, revoked sessions, reset the krbtgt password twice, rotated all service account credentials and rebuilt the compromised servers from known-good images. They wrote YARA rules for the loader and the implant, shared indicators of compromise with the national CERT, and blocked the command-and-control domains at the proxy and firewall. A forensic review of memory images confirmed that no rootkit remained and identified the exact vulnerability that allowed privilege escalation on an unpatched server.
