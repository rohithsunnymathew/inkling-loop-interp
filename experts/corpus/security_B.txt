The lessons were familiar. Multifactor authentication was enforced for most users but not for legacy protocols, so password spraying against the mail server succeeded. Local administrator passwords were reused, enabling lateral movement. Patching lagged for a remote code execution flaw with a public exploit, and an outdated VPN appliance exposed a path-traversal bug. Least privilege, network segmentation, application allow-listing, phishing-resistant authentication and immutable backups would each have broken the attack chain at a different stage.
Vulnerability management matters as much as detection. Each new CVE is scored for severity, but exploitability in the wild should drive priority, and known exploited vulnerabilities must be patched first. Penetration testers routinely find SQL injection in internal applications, cross-site scripting in web portals, insecure deserialization in Java services, buffer overflows in old firmware and default credentials on network devices. A web application firewall reduces exposure but does not fix the underlying flaw.
Threat intelligence adds context. Adversary groups reuse infrastructure, malware families and tradecraft, so a hash, an IP address or a TLS certificate fingerprint can link a new intrusion to a known campaign. Analysts pivot from one indicator to related domains, check reputation services, detonate suspicious files in a sandbox and record behaviour such as registry modifications, mutex creation, process injection and outbound connections. Good detections focus on behaviour rather than brittle signatures, because attackers can trivially recompile a payload to change its hash.
Cloud environments introduce their own attack surface. Over-permissive OAuth application consents, exposed storage buckets, leaked access keys in public repositories and misconfigured identity federation are common entry points. Attackers abuse illicit consent grants to read mailboxes, create inbox forwarding rules to hide replies, and register rogue applications with persistent permissions. Conditional access policies, privileged identity management, token protection and continuous monitoring of audit logs reduce that risk.
Security operations teams triage hundreds of alerts each day. Playbooks automate enrichment, such as looking up an IP address, checking whether a user is travelling, or querying the endpoint for related processes, so that analysts can decide quickly whether an alert is a true positive. False positives erode trust in the tooling, so detection rules need tuning, testing against replayed attack data and clear documentation of what each rule detects and how to respond.
